숫자 묶음 하나 = 방 안의 점 하나

원자료 카드 01/10 · @eeanimation방법: 숫자를 좌표로 읽기일상: 키·몸무게 기록표

왜 이 방법을 쓰나

  1. 문제 — 고객 기록표의 한 줄은 숫자 여러 개입니다. 이 줄끼리 얼마나 비슷한지 재고 싶습니다.
  2. 앞 방의 한계 — 숫자를 표로만 보면 "가깝다·멀다"를 한눈에 말하기 어렵습니다.
  3. 해법 — 숫자 하나를 칸 하나로 보고, 줄 하나를 방 안의 점 하나로 찍습니다.
쉽게 말하면 — 키만 적으면 수직선, 키·몸무게면 좌표평면, 하나 더하면 공간좌표입니다.

수학 수식을 어려워하는 조수가 대신 물어봅니다

조수 유클리드 공간, ℝⁿ… 이름부터 무서워요. 이게 뭔가요?

학교 수학으로 보면 — 수직선, 좌표평면, 공간좌표 — 그리고 두 점 사이의 거리

식 조각뜻
ℝ실수(소수점 있는 보통 숫자) 전체
ℝⁿ실수 n개를 한 줄로 묶은 것 전체 = n칸짜리 방
(x₁, …, xₙ)칸마다 숫자 하나씩 적은 점 하나
d(a, b) = |b − a|1칸 방의 거리 = 두 수의 차
숫자로 한 번 해 보기
1칸(키): 시아 160, 모아 163 → |163 − 160| = 3
2칸(키·몸무게): (160, 50)과 (163, 54) → √(3² + 4²) = √25 = 5
3칸(+허리): 허리 64와 76을 더하면 → √(3² + 4² + 12²) = √169 = 13
조수 칸이 늘어도 하는 일은 같네요. 차를 제곱해서 더하고 루트!

B − A = 집에서 회사까지 가는 화살표

왜 이 방법을 쓰나

  2. 앞 방의 한계 — 1번 방의 점은 자리만 알려 줍니다. 움직임은 담지 못합니다.
  3. 해법 — 끝점에서 출발점을 빼면 이동 화살표(벡터)가 나옵니다.
쉽게 말하면 — 점은 주소, 화살표는 "동쪽 3, 북쪽 2" 같은 길 안내입니다.

수학 수식을 어려워하는 조수가 대신 물어봅니다

조수 점이랑 벡터랑 둘 다 (3, 2)처럼 쓰는데 뭐가 달라요?

학교 수학으로 보면 — 벡터의 덧셈·뺄셈, 위치벡터

식 조각뜻
A, B자리(점)
v⃗ = B − AA에서 B로 가는 이동(화살표)
B = A + v⃗출발점에 이동을 더하면 도착점
OA⃗원점 O에서 A까지의 화살표(위치벡터)
숫자로 한 번 해 보기
A = (1, 1), B = (4, 3) → v⃗ = (4 − 1, 3 − 1) = (3, 2)
되돌려 보기: A + v⃗ = (1 + 3, 1 + 2) = (4, 3) = B
조수 숫자 모양은 같아도 점은 "여기", 화살표는 "이만큼 저쪽"이군요.

몇 칸이든 피타고라스

두 점 사이 거리 = 차의 제곱을 더하고 루트

원자료 카드 03/10 · @eeanimation방법: 피타고라스로 거리 재기일상: 지도에서 직선거리

왜 이 방법을 쓰나

  1. 문제 — "이 고객과 가장 비슷한 고객"을 찾으려면 멀고 가까움을 숫자 하나로 정해야 합니다.
  2. 앞 방의 한계 — 2번 방의 화살표는 숫자 두 개 이상이라 크기를 바로 비교할 수 없습니다.
  3. 해법 — 화살표를 빗변으로 보고 피타고라스 정리로 길이 하나를 냅니다.
쉽게 말하면 — 가로 3, 세로 4 걸으면 직선으로는 5만큼 떨어져 있습니다.

수학 수식을 어려워하는 조수가 대신 물어봅니다

조수 d(A, B) = √((b₁ − a₁)² + … + (bₙ − aₙ)²)… 점점점은 뭐예요?

학교 수학으로 보면 — 두 점 사이의 거리, 피타고라스 정리

식 조각뜻
bᵢ − aᵢi번째 칸의 차
( )²차를 제곱 — 음수도 양수가 된다
+ ⋯ +칸 수만큼 계속 더한다
√제곱을 풀어 원래 단위로 돌린다
숫자로 한 번 해 보기
A = (1, 1), B = (4, 5) → 가로 3, 세로 4 → √(9 + 16) = √25 = 5
3칸 예: (1, 1, 1)과 (3, 3, 2) → √(2² + 2² + 1²) = √9 = 3
골목길로 가면 3 + 4 = 7칸. 직선이 늘 가장 짧습니다
조수 점점점은 "칸 수만큼 반복"이었군요. 이제 안 무서워요.

왜 이 방법을 쓰나

  1. 문제 — 추천 앱은 "취향이 비슷한 사람"을 찾습니다. 양보다 방향이 중요합니다.
  2. 앞 방의 한계 — 3번 방의 거리는 많이 본 사람과 적게 본 사람을 멀다고 봅니다. 취향은 같아도요.

수학 수식을 어려워하는 조수가 대신 물어봅니다

조수 u·v = Σuᵢvᵢ = ‖u‖‖v‖cos θ… 시그마랑 이중 막대가 한꺼번에 나와요!

학교 수학으로 보면 — 벡터의 내적, 코사인

식 조각뜻
u·v겹침 점수(내적) — 같은 자리끼리 곱해서 더한 값
Σuᵢvᵢu₁v₁ + u₂v₂ + … (자리마다 곱해 모두 더하기)
‖u‖화살표 u의 길이(3번 방의 거리)
θ (세타)두 화살표 사이 각도
cos θ각도를 −1 ~ 1 점수로 바꾼 것. 같은 쪽 1, 직각 0, 반대 −1
숫자로 한 번 해 보기
u = (3, 0), v = (2, 2) → u·v = 3×2 + 0×2 = 6
길이: ‖u‖ = 3, ‖v‖ = √8 ≈ 2.83 → cos θ = 6 ÷ (3 × 2.83) ≈ 0.707 → θ = 45°
취향표(액션, 로맨스 본 편수): 시아 (5, 1), 모아 (4, 2) → 22 ÷ (5.10 × 4.47) ≈ 0.965
조수 cos θ가 1에 가까우면 "취향이 거의 같다"는 뜻이군요.

일상으로 치면

액션 5편·로맨스 1편 본 사람과 4편·2편 본 사람은 많이 닮았습니다. 0.965점입니다.

풀이

v를 (0, 2)로 옮기면 점수가 0이고 직각 표시가 뜹니다.

점수 0은 "쓸모없다"가 아니라 "서로 영향을 주지 않는다"는 뜻입니다. 동서와 남북처럼요.

0점은 길이가 0이 아닌 두 화살표일 때만 직각을 뜻합니다(원자료: nonzero vectors).

이 방의 한계 — 각도를 알아도 화살표를 "어떤 자로 재서" 숫자를 적었는지에 따라 좌표가 달라집니다. → 5번 방
교안의 파이썬 코드로 보면 (몰라도 됩니다)
u @ v / (np.linalg.norm(u) * np.linalg.norm(v))

좌표 숫자는 어떤 자로 재느냐에 따라 바뀐다

원자료 카드 05/10 · @eeanimation방법: 자 세트로 좌표 읽기일상: 길 안내 기준 바꾸기

왜 이 방법을 쓰나

  1. 문제 — 같은 데이터도 어떤 기준(축)으로 보느냐에 따라 숫자가 달라집니다.
  2. 앞 방의 한계 — 4번 방까지는 "가로·세로" 자를 당연하게 썼습니다. 다른 자를 쓰면 어떻게 될까요?
  3. 해법 — 길이 1이고 서로 직각인 자 세트(정규직교기저)를 쓰면 좌표 읽기가 겹침 점수 한 번으로 끝납니다.
쉽게 말하면 — 동서·남북으로 안내하든 "강 따라·강 건너"로 안내하든 목적지는 같습니다.

수학 수식을 어려워하는 조수가 대신 물어봅니다

조수 eᵢ·eⱼ = 1 아니면 0… 이 중괄호는 무슨 규칙이에요?

학교 수학으로 보면 — 좌표, 벡터의 성분, 회전

식 조각뜻
e₁, e₂자 세트의 자 두 개
v = 3e₁ + 2e₂e₁ 방향으로 3, e₂ 방향으로 2
eᵢ·eᵢ = 1자마다 길이 1
eᵢ·eⱼ = 0 (i ≠ j)서로 다른 자는 직각
좌표 = v·eᵢ그 자와의 겹침 점수가 곧 좌표
숫자로 한 번 해 보기
기본 자: v = (3, 2) → v·e₁ = 3, v·e₂ = 2
45° 돌린 자: e₁ = (0.71, 0.71), e₂ = (−0.71, 0.71) → 좌표 (3.54, −0.71)
길이 확인: 3.54² + 0.71² ≈ 12.5 + 0.5 = 13 = 3² + 2²
조수 숫자는 바뀌어도 제곱합 13은 그대로네요. 화살표 자체는 그대로라서요!

일상으로 치면

같은 장소도 "동쪽 3, 북쪽 2"와 "강 따라 3.5, 강 건너 −0.7"로 다르게 안내할 수 있습니다.

머신러닝에서는

원-핫 인코딩은 범주마다 길이 1인 직각 자를 하나씩 줍니다. 주성분 분석(PCA)은 데이터가 가장 넓게 퍼진 쪽으로 자 세트를 돌립니다.

박사자 세트를 돌려도 화살표는 그대로다. 숫자만 바뀌지.
