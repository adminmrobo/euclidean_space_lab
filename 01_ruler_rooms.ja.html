1軸・2軸・3軸の部屋、そしてn軸の部屋

なぜこの方法を使うのか

  1. 問題 — 顧客記録表の1行には数字がいくつも並んでいます。この行どうしがどれだけ似ているかを測りたいのです。
  2. 前の部屋の限界 — 数字を表で見るだけでは、"近い・遠い" をひと目で言うのは難しいです。

数式が苦手な助手が代わりに尋ねます

助手 名前が難しいです。数字をいくつか書くとそれが部屋になる、というのはどういう意味ですか？

2号室

点は位置、矢印は移動

B − A = 家から会社まで行く矢印

原資料カード 02/10 · @eeanimation方法：引き算で移動を求める日常：道案内

なぜこの方法を使うのか

  1. 問題 — 点が2つあると、"どこからどこへどれだけ" を言いたくなります。
  2. 前の部屋の限界 — 1号室の点は位置しか教えてくれません。動きは表せません。
  3. 解決法 — 終点から出発点を引くと、移動の矢印（ベクトル）が出てきます。
かんたんに言うと — 点は住所、矢印は "東へ3、北へ2" のような道案内です。

数式が苦手な助手が代わりに尋ねます

助手 点も矢印もどちらも (3, 2) のような形ですが、何が違うんですか？
ことばで言うと — 着いた場所から出発した場所を引くと、その間を進む矢印が出てきます。
数字で一度やってみる
A = (1, 1), B = (4, 3) → v⃗ = (4 − 1, 3 − 1) = (3, 2)
戻してみる：A + v⃗ = (1 + 3, 1 + 2) = (4, 3) = B

学校数学で見ると — ベクトルの足し算・引き算、位置ベクトル

式で見ると（開く — わからなくても大丈夫です）
v⃗ = B − A, B = A + v⃗
式のかけら意味
A, B位置（点）
v⃗ = B − AA から B へ行く移動（矢印）
B = A + v⃗出発点に移動を足すと到着点
OA⃗原点 O から A までの矢印（位置ベクトル）
助手 数字の形は同じでも、点は "ここ"、矢印は "これだけあっちへ" なんですね。

日常でいえば

家の住所（点）と "東へ3ブロック、北へ2ブロック"（矢印）は別の情報です。

機械学習では

2つのデータの差を矢印として見ます。単語の点で "王 − 男 + 女 ≈ 女王" のような計算をするのが、この部屋の引き算・足し算です。

博士A は家、B は会社です。通勤路を数字で言ってみましょうか？
シア図で見ると、緑の矢印が通勤路ですよね？
ショウジョウバエ研究員B をドラッグして動かしてみて。矢印の数字がどう変わるか見よう。
実験パネル 2原資料カード02の描き直し · 青い点 B をドラッグしてみてください

解説

B をどこへ動かしても、v⃗ = B − A がすぐについて変わります。

同じ矢印は、どこから出発しても同じ移動です。だから差を比べられます。

この部屋の限界 — 矢印は方向と量を教えてくれますが、"どれだけ遠いか" を数字1つでは言ってくれません。→ 3号室
確認クイズ — A = (2, 5)、B = (6, 2) のとき、A から B へ行く矢印は？
B − A = (6 − 2, 2 − 5) = (4, −3) です。終点（B）から出発点（A）を引きます：(6 − 2, 2 − 5)。
3号室

何軸でもピタゴラス

2点間の距離 = 差の二乗を足してルート

原資料カード 03/10 · @eeanimation方法：ピタゴラスで距離を測る日常：地図上の直線距離

なぜこの方法を使うのか

  1. 問題 — "この顧客にいちばん似た顧客" を探すには、遠い・近いを数字1つで決める必要があります。
  2. 前の部屋の限界 — 2号室の矢印は数字が2つ以上なので、大きさをすぐには比べられません。
  3. 解決法 — 矢印を斜辺と見て、ピタゴラスの定理で長さを1つ出します。
かんたんに言うと — 横に3、縦に4歩いたなら、出発点までの直線距離は5です。

数式が苦手な助手が代わりに尋ねます

助手 軸が増えたら距離はどうやって測るんですか？図が描けませんよね。
ことばで言うと — 軸ごとに差を求めて2乗し、すべて足してからルートをかけます。軸がいくつあっても同じ手順です。
数字で一度やってみる
A = (1, 1)、B = (4, 5) → 横 3、縦 4 → √(9 + 16) = √25 = 5
3軸の例: (1, 1, 1)と(3, 3, 2) → √(2² + 2² + 1²) = √9 = 3
路地を通ると 3 + 4 = 7 になります。直線がいつもいちばん短いです

学校数学で見ると — 2点間の距離、ピタゴラスの定理

式で見ると（開く — わからなくても大丈夫です）
d(A, B) = √((b₁ − a₁)² + (b₂ − a₂)² + ⋯ + (bₙ − aₙ)²)
式のかけら意味
bᵢ − aᵢi番目の軸の差
( )²差を二乗 — 負の数も正になる
+ ⋯ +軸の数だけ足し続けます
√二乗をほどいて元の単位に戻す
助手 点々は"軸の数だけくり返す"だったんですね。もう怖くありません。

日常でいえば

地図アプリの "直線距離 5km" がこの計算です。実際の道路距離はそれより長くなります。

機械学習では

最近傍探し（KNN）、似たもの同士をまとめる（K-means）がこの距離を使います。予測が外れた距離を2乗して軸の数で割ると、平均二乗誤差（MSE）になります。

モア軸が100個でも、この式はそのまま使えますか？
アバボット横に3、縦に4だから距離は7だよね！
ショウジョウバエ研究員怪しいなあ。A と B をドラッグして自分で測ってみて。

解説

アバボットの7は、路地を回り道した距離です。まっすぐな定規で測ると5です。

原資料の結論どおり、まっすぐな線分がいちばん短い道です。

原文：Straight segments give the shortest path.

ひと言でいうと — 身長・体重の記録で見ると、シアとモアの距離は 5 です。ほかの顧客と比べるときに使う数です。

4号室

重なりスコアと角度

2本の矢印がどれだけ同じ方向を向いているか

原資料カード 04/10 · @eeanimation方法：重なりスコア（内積）と cos θ日常：2人の好み表を比べる

なぜこの方法を使うのか

  1. 問題 — おすすめアプリは "好みが似た人" を探します。量より方向が大事です。
  2. 前の部屋の限界 — 3号室の距離は、たくさん見た人と少し見た人を遠いと判断します。好みは同じでもです。
  3. 解決法 — 同じ位置どうしを掛けて足した重なりスコアで、2本の矢印の間の角度を測ります。
かんたんに言うと — 2本の矢印が同じ方向ならスコアは大きく、直角なら0、反対なら負になります。

数式が苦手な助手が代わりに尋ねます

助手 2つの矢印が"同じ方を向いている"ことは、数字でどう言うんですか？
ことばで言うと — 同じ位置の数字どうしを掛けてすべて足すと、重なりスコアになります。2つの長さで割ると、−1~1 の間のスコア（cos θ）になります。
数字で一度やってみる
u = (3, 0), v = (2, 2) → u·v = 3×2 + 0×2 = 6
長さ：‖u‖ = 3、‖v‖ = √8 ≈ 2.83 → cos θ = 6 ÷ (3 × 2.83) ≈ 0.707 → θ = 45°
好み表（アクション、ロマンスを見た本数）：シア (5, 1)、モア (4, 2) → 22 ÷ (5.10 × 4.47) ≈ 0.965

学校数学で見ると — ベクトルの内積、コサイン

式で見ると（開く — わからなくても大丈夫です）
u·v = Σ uᵢvᵢ = ‖u‖ ‖v‖ cos θ
式のかけら意味
u·v重なりスコア（内積）— 同じ位置どうしを掛けて足した値
Σuᵢvᵢu₁v₁ + u₂v₂ + …（位置ごとに掛けてすべて足す）
‖u‖矢印 u の長さ（3号室の距離）
θ（シータ）2本の矢印の間の角度
cos θ角度を −1 〜 1 のスコアに変えたもの。同じ方向 1、直角 0、反対 −1
助手 cos θ が1に近ければ "好みがほぼ同じ" という意味なんですね。

日常でいえば

アクション5本・ロマンス1本を見た人と、4本・2本を見た人はとても似ています。0.965点です。

機械学習では

コサイン類似度で、似た商品・文書・顧客を探します。言語モデルのアテンションスコアも重なりスコアから出発しています。

博士式は開かなくても大丈夫です。まず数字でやってみて、気になったときだけ式を開いてみましょう。
シア同じ方向を向くとスコアが大きいなんて、矢印の相性ですね！
アバボットスコアが0なら関係ないってことだから、損切りしていいよね？
ショウジョウバエ研究員0になる位置を探してみて。v をドラッグして u と直角にしてみて。
実験パネル 4原資料カード04の描き直し · 緑の矢印 v の先をドラッグしてみてください

解説

v を (0, 2) に動かすとスコアが0になり、直角マークが出ます。

スコア0は "役に立たない" ではなく "互いに影響しない" という意味です。東西と南北のように。

0点が直角を意味するのは、長さが0でない2本の矢印のときだけです（原資料：nonzero vectors）。

一文で言うと — シアとモアの好み表は0.965点 — 1にとても近いので、好みはほぼ同じ方向です。

AI判定コーナー — そのまま信じていいでしょうか？

AIが2人の顧客のコサイン類似度（cos θ）を1.3だと答えました。信じていいでしょうか？

確かめてみる

cos θはいつも−1から1の間です。1.3はありえない値なので、計算をやり直させてください。長さで割る段階を抜かした可能性が高いです。

この部屋の限界 — 角度がわかっても、矢印を "どの定規で測って" 数字を書いたかによって座標が変わります。→ 5号室
教材の Python コードで見ると（わからなくても大丈夫です）
u @ v / (np.linalg.norm(u) * np.linalg.norm(v))

重なりスコアを2つの長さの積で割って、cos θ（コサイン類似度）を求めます。

結果: 0.7071… — 手で求めた6 ÷ (3 × 2.83) ≈ 0.707と同じです。

確認クイズ — u = (1, 2)、v = (−2, 1) の重なりスコアは？2本の矢印はどんな関係ですか？
1×(−2) + 2×1 = 0なので直角です。位置ごとにかけて足してみてください：1×(−2) + 2×1。
5号室

長さ1で互いに直角な定規セット

座標の数字はどの定規で測るかによって変わる

原資料カード 05/10 · @eeanimation方法：定規セットで座標を読む日常：道案内の基準を変える

なぜこの方法を使うのか

  1. 問題 — 同じデータでも、どの基準（軸）で見るかによって数字が変わります。
  2. 前の部屋の限界 — 4号室までは "横・縦" の定規を当たり前に使ってきました。別の定規を使うとどうなるでしょう？
  3. 解決法 — 長さ1で互いに直角な定規セット（正規直交基底）を使えば、座標読みは重なりスコア1回で終わります。
かんたんに言うと — 東西・南北で案内しても、"川沿い・川向こう" で案内しても、目的地は同じです。

数式が苦手な助手が代わりに尋ねます

助手 物差しを変えると座標の数字も変わるそうですが、それでも同じ矢印なんですか？
ことばで言うと — 長さ1で互いに直角な物差しを2本当てて、それぞれの物差しとの重なりスコアを読むと、それが座標です。矢印の長さはそのままです。
数字で一度やってみる
基本の定規：v = (3, 2) → v·e₁ = 3、v·e₂ = 2
45° 回した定規：e₁ = (0.71, 0.71)、e₂ = (−0.71, 0.71) → 座標 (3.54, −0.71)
長さの確認：3.54² + 0.71² ≈ 12.5 + 0.5 = 13 = 3² + 2²

学校数学で見ると — 座標、ベクトルの成分、単位ベクトル

式で見ると（開く — わからなくても大丈夫です）
v = 3e₁ + 2e₂, eᵢ·eⱼ = 1 (同じ物差し), 0 (違う物差し)
式のかけら意味
e₁, e₂定規セットの定規2本
v = 3e₁ + 2e₂e₁ 方向に 3、e₂ 方向に 2
eᵢ·eᵢ = 1定規ごとに長さ1
eᵢ·eⱼ = 0 (i ≠ j)別々の定規は直角
座標 = v·eᵢその定規との重なりスコアがそのまま座標
助手 数字は変わっても、二乗和13はそのままですね。矢印そのものは変わらないからです！

日常でいえば

同じ場所でも、"東へ3、北へ2" と "川沿いに3.5、川向こうへ −0.7" のように違う案内ができます。

機械学習では

ワンホットエンコーディングは、カテゴリーごとに長さ1の直角な定規を1本ずつ与えます。主成分分析（PCA）は、データがいちばん広く散らばった方向へ定規セットを回します。

博士定規セットを回しても、矢印はそのままです。数字が変わるだけです。
モアでも座標が違ったら、別のデータじゃないんですか？
ショウジョウバエ研究員スライダーで定規セットを回しながら、二乗和を見張ってて。
実験パネル 5原資料カード05の描き直し · 定規セットを回してみてください

解説

原資料の結論どおり、座標は選んだ定規セットによって変わります。

原文：Coordinates depend on the chosen basis.

それでも長さと角度はそのままです。だから定規を替えても同じデータです。

この部屋の限界 — 定規セットで座標は読めましたが、正解にぴったり合わせられないときに "いちばん近い答え" を選ぶ方法はまだありません。→ 6号室
確認クイズ — 長さ1で互いに直角な定規セットで、v の1つ目の座標はどう求めますか？
座標 = v·e₁です。ものさしの長さが1で、互いに直角だからできることです。ものさしセットが長さ1・直角なら、重なりスコア1回がそのまま座標です。

第①編のまとめ

部屋道具ひとこと機械学習では
1点数字の並び1つ = 点1つデータ1行
2矢印B − A = 移動埋め込みの差
